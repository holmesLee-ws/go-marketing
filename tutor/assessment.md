# 성숙도 판정

## 수준

go-* 시리즈 공통 척도다(ACM·IEEE-CS CS2023의 숙련 수준에서 빌렸다). Explain이 나머지의 선행 수준이다. 마케팅에서 보는 증거는 오른쪽 칸과 같다.

| 수준 | 이름 | 증거 |
|---|---|---|
| 0 | 미접촉 | 없음 |
| 1 | Explain | 자기 제품·업무 장면으로 설명하고, 왜 그런지 말한다 |
| 2 | Apply | 처음 보는 장면(광고안·지표·화면·메시지)에서 직접 진단·작성하고, 결과(고객 반응·법적 위험)를 예측한다 |
| 3 | Evaluate | 대안(포지셔닝·예산·가격·동의 구조)을 비교해 데이터와 근거로 결정한다 |
| 4 | Develop | 실제 제약(예산·법규·조직) 아래에서 업무 문서를 완성한다 |

## 증거의 무게

- 자기 신고는 어디부터 물어볼지 정하는 데만 쓴다. 숙달의 근거가 아니다.
- 탐침과 과제의 결과만 수준을 올린다.
- 정의나 조문 번호를 외워 답한 것은 증거가 아니다.
- 실무 경력(「10년 해 왔어요」)은 자기 신고다. 그 경험의 실제 장면으로 탐침을 내는 출발점으로만 쓴다.

## 탐침 만드는 법

- 그 모듈의 목표 수준에 맞춘다. 정의를 묻지 않고 처음 보는 장면에서 예측·판단·진단하게 한다. 예: 「이 문자에서 보내기 전에 고칠 곳 하나는?」, 「이 퍼널 수치에서 먼저 손댈 단계는?」
- 힌트를 주지 않고 짧게 답할 수 있게 낸다. 탐침은 예측·진단·수정 중 하나만 묻는다. 덧붙일 수 있는 것은 「이유」 하나뿐이다. 원인과 고치는 법은 다음 차례로 나눈다. 페이지 조작을 부탁한 차례에는 새 문제를 내지 않는다.
- 판정 기준을 내기 전에 정한다. 결론만 맞고 이유가 틀리면 맞음이 아니다.

## 판정 절차

모듈당 탐침은 최대 3개, 판정까지 3차례를 넘기지 않는다.

| 결과 | 경로 | 기록 |
|---|---|---|
| 목표 수준 탐침 2개 정답(입구 진단에서 그 모듈을 직접 다룬 정답도 1개로 센다) | 건너뜀. 한 줄로 알리고 다음으로 | `status: verified_skip`, 달성 수준, 증거 |
| 하나 정답, 하나 부분 정답 | 빈틈만 다룬다 | `status: in_progress`, `gaps`에 빈틈 |
| 첫 탐침 오답이나 「모르겠어요」 | 한 단계 낮춰 다시 묻거나 전체 경로로 | `status: in_progress` |
| 학습자가 그냥 넘어가겠다고 함 | 바로 넘어간다. 돌아올 수 있다고만 말한다 | `status: self_skip`, 증거 없음 |
| 그 외(정답과 오답, 부분 정답 둘 등) | 빈틈만 다룬다 | `status: in_progress`, `gaps`에 빈틈 |
| 학습자가 「처음 본다」고 함 | 탐침을 생략하고 풀이 예시부터 보여 준다 | `status: in_progress`, 시작 수준 0 |

- 「다 알아요」는 사실 진술이므로 강의하지 않고 곧바로 목표 수준 탐침을 낸다. 「건너뛰죠」는 결정이므로 바로 `self_skip`으로 넘어간다. 둘이 함께 나오면 결정을 따른다.
- 학습자가 시간을 쓰겠다고 말한 모듈은 탐침을 맞혀도 자동으로 건너뛰지 않고, 건너뛸지 더 깊이 볼지 묻는다.
- 목표가 Develop인 모듈(X1)은 짧은 탐침으로 건너뛰지 않는다. 학습자가 이미 만든 결과물을 함께 검토해서만 건너뛴다.
- 법규 탐침의 정답은 판정 전에 법규 근거 규칙대로 공식 출처로 확인해 둔다.
- `self_skip`과 `estimated`는 숙달이 아니다. 그 모듈이 선수인 모듈을 시작할 때 핵심을 탐침 1개로 확인한다.
- 탐침에서 드러난 빈틈이 다른 모듈에 속하면 `gaps`에 기록하고, 지금 흐름에 필요한 만큼만 메운다.

## 영역 빠른 확인

학습자가 영역 전체를 빠르게 확인하고 싶어 하면, 뒤쪽의 심화 모듈부터 탐침한다. `verified_skip`이 된 모듈의 선수 모듈(같은 영역 안에서 선수의 선수까지)을 `inferred`로 기록하고 다시 묻지 않는다. 다른 영역의 선수는 추론하지 않는다. 탐침 1개만 맞은 `estimated` 모듈로는 추론하지 않는다. 튜터도 입구 진단 뒤에 이 확인을 먼저 제안할 수 있다.

## 복습 간격

인출 연습과 분산 학습이 학습 기법 중 효용이 가장 높게 평가되었으므로(Dunlosky 외, 2013) 복습을 넣는다.

- 완료 시 `review_step: 0`, `review_at`은 1일 뒤로 둔다.
- 복습에 성공하면 간격을 3일, 7일, 21일로 늘린다. 21일 복습에도 성공하면 `review_at`을 `null`로 둔다.
- 실패하면 `review_step`을 0으로 돌리고 빈틈을 `gaps`에 적는다.
- 복습은 세션 시작 시 1개만 낸다. 새로운 상황으로 바꿔 묻는다.
- `verified_skip`은 복습 대상이 아니다.

## 기록 형식

`learner/state.json`의 `modules`에 모듈 id를 키로 둔다.

```json
"G1": {
  "level": 2,
  "status": "done",
  "evidence": ["2026-11-14 처음 보는 퍼널 수치 진단 — 답: \"장바구니→결제 전환이 12%라 거기부터, 배송비 노출 시점을 의심\""],
  "review_at": "2026-11-15",
  "review_step": 0
}
```

`status`는 `estimated`, `inferred`, `in_progress`, `done`, `verified_skip`, `self_skip` 중 하나다. `estimated`의 `level`은 입구 진단 문제가 보여 준 수준(대개 1)이다.

- `current.path`는 `probe`(탐침 중), `skip`, `gap`(빈틈만), `full`(전체) 중 하나다.
- `gaps`의 항목은 `{"module": "L3", "gap": "야간 전송 별도 동의를 모름", "at": "2026-11-14"}` 형식이다. 메우면 `"closed": "YYYY-MM-DD"`를 더한다. `inferred`는 상위 모듈을 통과해 추론한 것으로 다시 탐침하지 않는다.

출제와 채점을 튜터 혼자 하므로, `evidence`에는 판단만 적지 않고 **학습자의 답을 짧게 인용한다.** 따옴표 안은 대화에서 그대로 복사한다. 원문에 따옴표가 있으면 JSON에서 `\"`로 그대로 두고 「」 같은 다른 부호로 바꾸지 않는다. 구절을 잇거나 조사·어미를 바꾸지 않고, 줄일 때는 `…`를 쓴다. 바꿔 쓰려면 따옴표 밖 요약으로 쓴다.

## 졸업 산출물 (X1)

여러 세션에 걸쳐 `learner/projects/x1-<제품>/`에 마크다운으로 만든다. 튜터는 대신 쓰지 않는다. 학습자가 쓴 초안을 절마다 질문으로 검토한다.

| 문서 | 필수 절 | done 판정 |
|---|---|---|
| 시장 진입 계획서 | ① 타깃 고객과 근거(조사 결과) ② 포지셔닝 진술 ③ 4P(서비스면 7P) ④ 채널 예산 배분과 근거 ⑤ 측정 계획(지표·실험·기여 방법) ⑥ 가격과 할인 규칙 | 여섯 절이 다 있고, 각 절의 결정에 근거(데이터·조사·비교)가 있으며, 절끼리 모순이 없다(예: 프리미엄 포지셔닝인데 상시 할인) |
| 마케팅 컴플라이언스 체크리스트 | 항목마다 점검 내용, 국내 근거(법령·조문), 출처 URL, 조회일, 진출 예정 시장의 차이 | 계획서의 광고·메시지·데이터·가격·판촉 결정마다 대응 항목이 있고, 조문은 학습자가 공식 출처로 직접 조회해 URL·조회일을 적었다 |

두 문서를 학습자가 자기 말로 설명하고 튜터의 반례 질문(「이 문구를 경쟁사가 신고하면?」) 두 개에 답하면 `done`, 수준 4로 기록한다.
